| BSL-01 | RESOLVED | Before ADR 0035 the gateway applied no budget-derived token limit: `ccofPersonTpm` came from the family policy only, and the rebuilt decision dropped `personCeilingTokensPerMinute` (`infra/gateway/policy/claude-messages.template.xml`, `git log -S personCeilingTokensPerMinute -- infra` is empty). Budget overshoot was bounded only by the reconciler delay. |
| BSL-02 | RESOLVED | `llm-token-limit` counts prompt and completion tokens only, and on v2 tiers one counter key must carry one `tokens-per-minute` value. Source: [llm-token-limit](https://learn.microsoft.com/azure/api-management/llm-token-limit-policy), retrieved 2026-10-24. The pace prices every counted token at the worst output rate; cache tokens are not counted. |
| BSL-03 | ASSUMED | Reconciler delay (ingestion plus interval) stays within the pacing window. Measured about nine minutes on Fabrikam lab 2026-10-23 (session `files\usage-test`). Total delay including interval and decision cache is about 13 minutes; examples use a 30-minute window because a 10-minute window allowed about 149% in a review simulation. A longer delay weakens the bound; `maxIngestionDelaySeconds` on the run line shows it. |
| BSL-04 | RESOLVED | Measured 2026-10-24 on the lab deployment ([ADR 0035](adr/0035-budget-soft-limit-and-spend-pacing.md#live-test-2026-10-24-lab-deployment-sonnet-5-12-parallel-streams-80--30-minutes)): $25 budget ended at $27.03 (108.1%), $35 budget at $37.11 (106.0%). Ledger totals matched the client totals. |
| BSL-05 | OPEN | A per-minute token counter admits all waiting streams at once when it refills or its key changes, and APIM counts a stream only when it finishes. Overshoot is about one burst of a person's parallel requests (12 Sonnet streams: about $1.92). Run 3 (2026-10-24, power-of-two ceiling, no reservation) ended $0.18 over a $52.11 budget, so the burst is not certain to occur. A per-request reservation (local branch `feat/budget-burst-reservation`, `5b5b820`) was rejected in code review on 2026-10-24: with an expression `increment-count`, APIM postpones the count to the end of the outbound pipeline, so simultaneous requests are all admitted ([rate-limit-by-key](https://learn.microsoft.com/azure/api-management/rate-limit-by-key-policy)); and charging `max_tokens` per request caps request count for people under budget. Candidate next approach: a per-person concurrency cap, after confirming `limit-concurrency` support on v2 tiers. |
| DR-01 | RESOLVED | Supplied third environment and Fabrikam lab share the tenant ID provided for this work, but use different subscriptions. Subscription access, resource ownership and network connectivity still require read-back; same-tenant is not permission to modify resources. Private evidence is outside git. |

Project-specific opt-in must not alter a shared direct backend used by projects with failover off. Use project/routing-revision-scoped pool member entities. Source: [APIM backends](https://learn.microsoft.com/azure/api-management/backends). |
